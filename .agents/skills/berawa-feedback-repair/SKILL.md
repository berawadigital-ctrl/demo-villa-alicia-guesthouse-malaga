# Aprendizaje técnico continuo

Activar después de al menos tres auditorías o tras un fallo crítico repetido.

1. Recopilar informes vinculados a SHA y evidencias verificables.
2. Clasificar problemas (idiomas, móvil, chatbot, hechos, licencias, CTA, rendimiento, seguridad, ZIP).
3. Diferenciar fallos aislados de patrones de fabricación; calcular cuántas demos afecta cada patrón.
4. Proponer una mejora concreta para la Skill de Grok, con redacción «antes/después», riesgo, coste esperado y prueba de regresión que debería fallar antes y pasar después.
5. Presentar el cambio a Juan para su aprobación. No reescribir automáticamente las Skills maestras ni cambiar la oferta económica, horarios, filtros de prospección o sistema de supervisión.
6. Guardar propuesta versionada e indicar qué nueva prueba de fabricación permitirá comprobar su resultado.

Salida: propuesta breve con evidencia, causa probable, cambio propuesto, prueba reproducible, indicador esperado y decisión humana pendiente.
